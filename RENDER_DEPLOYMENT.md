# FoodWise Pro v21 — Render deployment

## What production uses
- **Firebase Authentication**: Email/Password signup/login, Forgot Password email, Change Password.
- **MongoDB Atlas**: users, household/app state, persistent server sessions, inventory/planner/history, and GridFS generated images.
- **Render**: hosts the Node.js server and PWA from this repository.

## Firebase
1. Firebase Console → Authentication → Sign-in method → enable **Email/Password**.
2. Authentication → Templates → Password reset can be customized.
3. Copy the project's **Web API Key** and use it as `FIREBASE_API_KEY` in Render.
4. Add your deployed Render hostname under Firebase Authentication authorized domains when required by your Firebase project settings.

## MongoDB Atlas
1. Create a cluster and database user.
2. Allow network access for the Render service. For demos, `0.0.0.0/0` is simple but should be tightened for production.
3. Copy the `mongodb+srv://...` URI into Render as `MONGODB_URI`.

## Render / GitHub
1. Push this folder to a GitHub repository. `.env`, local JSON state and local auth are ignored by `.gitignore`.
2. Render → **New → Blueprint** → select the repository. `render.yaml` is already included.
3. Fill secret environment variables: `MONGODB_URI`, `FIREBASE_API_KEY`; optional AI keys can be added too.
4. `SESSION_SECRET` is generated by the Blueprint.
5. Deploy, then open `/api/health`. It should report `mode: cloud`, `storage: MongoDB`, `mongo: connected`, and Firebase configured.

## Localhost
Use `.env.example` as a template. With `LOCAL_MODE=true`, MongoDB/Firebase are not required for basic localhost development.

## Security
Never commit `.env`, MongoDB credentials, Firebase private credentials, Gemini keys or Cloudflare tokens. Firebase passwords are not stored in MongoDB.
